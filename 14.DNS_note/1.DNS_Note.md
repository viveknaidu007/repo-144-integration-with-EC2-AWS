DNS Notes: Comprehensive Guide
What is DNS?
The Domain Name System (DNS) translates human-readable domain names (e.g., theadtip.in) into machine-readable IP addresses (e.g., 192.0.2.1). It acts like a phonebook for the internet, ensuring users can access websites using names instead of numerical addresses.
Common DNS Record Types
DNS records define how a domain or subdomain behaves. Below is a table of commonly used DNS record types, their full forms, and purposes.

Notes on Common Types

A Record: Directly links a domain/subdomain to an IPv4 address. Essential for website or API hosting.
AAAA Record: Same as A but for IPv6, which supports more devices and is future-proof.
CNAME Record: Useful for aliasing (e.g., making api.theadtip.in point to server.theadtip.in). Cannot point to an IP directly.
MX Record: Critical for email delivery. Multiple MX records can exist with different priorities.
TXT Record: Versatile for storing metadata or verifying domain ownership.

Time to Live (seconds). Defines how long DNS resolvers cache the record before querying again.

Proxy Status
Determines if the traffic is proxied through a service (e.g., Cloudflare) or DNS-only (direct to server).
Proxied or DNS Only


TTL (Time to Live)

Purpose: TTL controls how long DNS resolvers (e.g., ISPs) cache a DNS record. Lower TTL means faster updates but more queries to your DNS server.
Common Values:
300 (5 minutes): For frequent changes (e.g., during server migrations).
3600 (1 hour): Balanced for most cases.
86400 (24 hours): For stable setups with rare changes.


Impact: If you change an A record’s IP, a high TTL (e.g., 86400) means users may see the old IP for up to 24 hours. Low TTL reduces this delay.

Proxy Status

DNS Only: The DNS record resolves directly to the server’s IP. No intermediary (e.g., Cloudflare) processes the traffic. Use this for APIs or services that don’t need CDN features.
Proxied: Traffic routes through a proxy (e.g., Cloudflare), which can provide:
CDN: Caches content for faster delivery.
Security: DDoS protection, WAF (Web Application Firewall).
IP Hiding: Your server’s IP is masked by the proxy’s IP.


Choosing Proxy Status:
For api.theadtip.in, use DNS Only if it’s an API server, as proxies may interfere with non-HTTP traffic.
Use Proxied for websites needing performance and security.



Steps to Add Subdomain api.theadtip.in and Link to Server IP
Assuming you have:

Domain: theadtip.in
DNS managed by a provider (e.g., Cloudflare, GoDaddy, or Namecheap).
Server IP: Let’s say 203.0.113.10 (replace with your actual server IP).

Step-by-Step Guide

Log in to Your DNS Provider:
Access your DNS management panel (e.g., Cloudflare’s DNS tab, GoDaddy’s DNS Management).


Add an A Record for api.theadtip.in:
Create a new DNS record with these details:
Type: A
Name: api (this becomes api.theadtip.in)
Content: 203.0.113.10 (your server IP)
TTL: 3600 (or lower if testing)
Proxy Status: DNS Only (for APIs, to avoid proxy interference)


Save the record.


Verify DNS Propagation:
Wait for DNS to propagate (minutes to hours, depending on TTL).
Use tools like dig api.theadtip.in or nslookup api.theadtip.in to confirm the IP resolves correctly.
Online tools: whatsmydns.net or dnschecker.org.


Configure Your Server:
Ensure your server (at 203.0.113.10) is configured to handle requests for api.theadtip.in.
For example, if using Nginx, add a server block:server {
    listen 80;
    server_name api.theadtip.in;
    # Your API configuration
}


Restart your server (e.g., sudo systemctl restart nginx).


Test the Subdomain:
Access api.theadtip.in via browser or API client (e.g., Postman).
If it doesn’t work, check:
DNS propagation status.
Server configuration.
Firewall rules (ensure port 80/443 is open on 203.0.113.10).
